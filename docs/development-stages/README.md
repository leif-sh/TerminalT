# FastTerm 基础版阶段开发文档

本目录将《FastTerm 基础版 SSH 客户端功能开发文档》中的功能范围拆分为可独立计划、开发和验收的阶段。开发应按阶段顺序推进；如果并行开发，仍需满足各文档列出的前置依赖和接口约束。

## 阶段总览

| 阶段 | 文档 | 阶段成果 | 建议里程碑 |
| --- | --- | --- | --- |
| 0 | [工程基础与架构骨架](./STAGE_0_FOUNDATION.md) | 可扩展的 Tauri、React、Rust 工程骨架 | 工程基线 |
| 1 | [SSH 单会话最小闭环](./STAGE_1_SSH_MVP.md) | 能通过密码或私钥进入远程 Shell | 内部 Alpha |
| 2 | [连接资产与安全凭据](./STAGE_2_CONNECTIONS_AND_CREDENTIALS.md) | 可安全保存、组织和复用连接 | Alpha 完整版 |
| 3 | [多会话与完整终端体验](./STAGE_3_TERMINAL_EXPERIENCE.md) | 满足日常使用的多标签终端 | 功能 Beta |
| 4 | [基础 SFTP 文件能力](./STAGE_4_SFTP.md) | SSH 与基础文件传输闭环 | 功能完整 Beta |
| 5 | [设置、数据迁移与诊断](./STAGE_5_SETTINGS_AND_DIAGNOSTICS.md) | 配置、备份和问题诊断能力完整 | RC |
| 6 | [稳定性、安全与发布](./STAGE_6_RELEASE.md) | 达到 Windows 基础版发布标准 | v1.0 |

## 执行规则

1. 每个阶段开始前，确认上一阶段的退出条件已经满足。
2. 功能开发必须同时完成对应的异常路径、资源释放和测试，不把这些工作统一推迟到阶段 6。
3. 阶段 6 是系统级加固和发布验收，不替代各阶段自身的功能验收。
4. 未列入基础版的能力不得在阶段开发中顺带实现；新增范围必须先更新总功能文档和对应阶段文档。
5. 前端、Rust 后端和测试任务应围绕同一个稳定数据模型与错误码契约开发。

## 阶段状态建议

每个阶段可使用以下状态管理：

- `未开始`：前置条件未满足或尚未排期；
- `开发中`：功能与自动化测试正在实现；
- `联调中`：前后端契约稳定，正在进行真实服务器验证；
- `验收中`：功能冻结，只修复本阶段缺陷；
- `已完成`：退出条件全部满足且无阻断级、严重级缺陷。
