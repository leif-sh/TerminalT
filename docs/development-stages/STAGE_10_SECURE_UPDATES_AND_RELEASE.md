# 阶段 10：安全更新与发布

## 1. 阶段目标

在现有 NSIS 安装和本地发布校验基础上，建立签名、可回退、可诊断的应用更新链路。阶段结束时，已安装版本可以检查、下载并安装可信的新版本；任何网络、签名或安装失败都不会破坏当前可运行版本和用户数据。

## 2. 前置条件

- 阶段 7 的数据迁移和凭据安全回归通过。
- 确认 Tauri 2 updater 方案、支持的签名算法和 Windows 安装交接行为。
- 确定稳定更新源、发布清单格式、HTTPS 托管和访问控制。
- 在受控发布环境生成更新签名密钥，私钥不得进入仓库或开发机默认配置。
- 准备至少两个旧版本、当前版本和一个模拟未来版本的升级测试包。

阶段 10 可与阶段 8、9 并行，但正式发布前必须重新回归当时最新数据 schema。

## 3. 范围与非范围

本阶段包含：

- 稳定更新通道；
- 手动检查和可配置启动检查；
- 版本说明、下载进度、签名/哈希校验和安装交接；
- 更新失败继续运行旧版本；
- 降级、同版本重复安装和不兼容 schema 保护；
- 发布清单、安装包、签名和校验和自动化；
- 干净安装、覆盖升级、卸载和重装回归。

本阶段不包含：

- 未经用户授权的后台静默安装；
- Beta/Canary 多通道，稳定通道验证后另行规划；
- 自定义驱动或系统服务；
- 云账号、设备管理和企业强制升级；
- 从不受信任 URL 临时切换更新源。

## 4. 更新模型

### 4.1 更新状态

```ts
type UpdateState =
  | 'idle'
  | 'checking'
  | 'available'
  | 'downloading'
  | 'ready'
  | 'installing'
  | 'failed'
```

- 运行状态不持久化为“安装成功”；下次启动读取实际应用版本确认结果。
- 下载中断后是否续传由 updater 能力决定，不提供无法保证的伪状态。
- 用户拒绝本次更新只记录版本和时间，不永久屏蔽安全更新。

### 4.2 更新清单

至少包含：

- 应用版本和发布日期；
- Windows 平台、架构和安装包 URL；
- 安装包哈希和签名；
- 最低可直接升级版本；
- 发布说明 URL 或内嵌摘要；
- 是否包含数据 schema 迁移提示。

清单和包都必须通过 HTTPS 获取，包签名使用应用内固定公钥验证。

## 5. 详细开发功能

### 5.1 检查更新

- 设置页显示当前版本、通道和最近检查结果。
- 支持用户点击“检查更新”。
- 启动检查默认不阻塞首屏，失败只产生非阻断提示。
- 版本比较遵循项目 `MAJOR.MINOR.PATCH-N` 规则，不使用字符串字典序。
- 同版本返回已是最新版本，高版本客户端拒绝低版本清单。
- 网络超时、TLS、清单格式和服务器错误分别映射。

### 5.2 下载与校验

- 展示文件大小、下载进度和取消操作。
- 下载到受控临时目录，不覆盖安装目录中的当前可执行文件。
- 安装前完成签名和哈希校验，任一失败删除不可信临时包。
- 限制重定向和允许的更新域名，禁止 `file:` 等非 HTTPS 来源。
- 日志只记录版本、状态、耗时和错误码，不记录可能包含令牌的完整 URL。

### 5.3 安装交接

- 安装前提示版本、发布说明和需要重启。
- 活动 SSH、SFTP 和隧道存在时提示其将被关闭。
- 用户确认后走统一应用退出流程，有界关闭任务再交给安装器。
- 安装器失败时当前版本仍可再次启动。
- 首次启动校验实际版本、数据迁移和设置可读性，并记录脱敏结果。

### 5.4 数据兼容和回退

- 更新前对关键配置文件做受控备份或确保迁移本身可原子回滚。
- schema 迁移失败保留原始文件并阻止写入新格式。
- 不承诺任意版本降级读取新 schema；降级必须明确阻止或提示兼容风险。
- 卸载默认不删除用户连接、凭据和 known-host 数据，行为与现有说明一致。

### 5.5 发布自动化

- 构建前验证五处应用版本一致。
- 运行 lint、前后端测试、构建、Clippy、安全审计和产物检查。
- 生成 NSIS 安装包、更新包、SHA-256、签名和更新清单。
- 校验清单 URL、版本、哈希和签名对应同一产物。
- 构建来源、提交、工具版本和签名结果归档。
- 发布私钥仅由受控 CI secret 或离线签名流程使用。

### 5.6 错误码

至少覆盖：

```text
UPDATE-CHECK-FAILED
UPDATE-MANIFEST-INVALID
UPDATE-NOT-SUPPORTED
UPDATE-DOWNLOAD-FAILED
UPDATE-SIGNATURE-INVALID
UPDATE-HASH-MISMATCH
UPDATE-INSTALL-FAILED
UPDATE-MIGRATION-FAILED
```

## 6. 安全要求

- 签名失败必须关闭更新路径，不能让用户点击“仍然安装”。
- 更新公钥随应用发布并受代码审查保护。
- 签名私钥不得写入仓库、日志、安装包和普通构建缓存。
- 更新源固定且最小化，不读取远端清单中的任意执行参数。
- 安装前不运行下载包中的任何辅助程序。
- 更新不能改变 Windows 安全设置或绕过安装权限边界。
- CSP、Tauri capability 和 updater 权限按最小范围配置。

## 7. 测试与验证

### 7.1 功能矩阵

- 旧版本到新版本升级，连接、分组、设置、known-host 和凭据引用保持完整。
- 已是最新、发现更新、用户取消、下载取消和稍后更新。
- 同版本、低版本、格式错误和不支持平台清单。
- 更新后首次启动、再次重启和卸载重装。

### 7.2 故障与攻击测试

- 清单篡改、包篡改、错误签名、哈希不一致。
- TLS 失败、DNS 失败、超时、重定向异常和下载中断。
- 磁盘不足、临时目录不可写和安装器返回失败。
- 更新前应用强制退出、迁移中断和损坏配置恢复。
- 包 URL 注入、路径穿越和不允许协议。

### 7.3 Windows 验收

- Windows 10 1809 和 Windows 11。
- 当前用户安装、覆盖升级、卸载、重装。
- 活动会话/传输/隧道关闭提示和资源释放。
- 安装后快捷方式、应用版本、开发者工具和 capability。

## 8. 任务拆分

1. updater 技术验证和威胁建模。
2. 更新清单、版本比较和设置模型。
3. 检查、下载、取消和错误映射。
4. 签名/哈希校验和固定更新源。
5. 安装交接、退出协调和首次启动确认。
6. 发布流水线、密钥管理和产物验证。
7. 多版本升级、故障注入和 Windows 验收。

## 9. 阶段交付物

- updater 架构、威胁模型和密钥管理说明。
- 设置页更新界面和完整状态处理。
- 签名更新链路与发布自动化。
- 多版本升级、篡改测试和 Windows 安装验收记录。
- 更新后的发布手册、回滚说明和用户文档。

## 10. 退出条件

- 受支持旧版本能安全升级且用户数据完整。
- 篡改、错误签名和哈希不一致均无法进入安装步骤。
- 所有失败场景仍能启动原版本。
- 版本、产物、清单、哈希和签名自动校验一致。
- 活动任务在安装前按统一退出流程释放。
- 私钥和发布秘密扫描零命中，无阻断级或严重级缺陷。
